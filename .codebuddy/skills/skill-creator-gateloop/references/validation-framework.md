## Layer 1：可发现性测试

测试 description 是否在预期输入上正确触发（和不触发）。

### 应触发提示词（需要 100% 匹配率）

生成 3 个必须激活此 skill 的提示词：

| # | 提示词 | 预期触发置信度 | 测试内容 |
|---|-------|--------------|---------|
| 1 | [直接使用关键词] | 100% | 主要触发词 |
| 2 | [同义词/相关上下文] | >90% | 语义匹配 |
| 3 | [不同语言（如有多语言）] | >80% | 多语言支持 |

### 不应触发提示词（需要 0% 匹配率）

生成 3 个必须不激活的提示词：

| # | 提示词 | 可能误触的原因 | 测试内容 |
|---|-------|--------------|---------|
| 1 | [反触发区提示词] | 领域相似但意图错误 | 边界精度 |
| 2 | [听起来像但不同] | 词汇重叠 | 消歧能力 |
| 3 | [通用无关提示词] | 存在宽泛术语 | 假阳性抵抗 |

### 评估协议

```
针对 skill 选择运行每个提示词：
├─ 3 个应触发都触发了？     → ✅ 通过
├─ 有任何应触发被遗漏？      → ❌ 修复：向 description 添加缺失关键词
├─ 3 个不应触发都静默？      → ✅ 通过
└─ 有任何不应触发被误触发？   → ❌ 修复：加强反触发措辞
```

## Layer 2：逻辑测试

针对真实测试提示词模拟 agent 逐步执行。

### 模拟流程

```
测试提示词："[真实用户输入]"

步骤 1："[工作流中的指令]"
  预期：[agent 应在此做什么]
  Agent 会：[预测 agent 行为]
  匹配？是/否 → 若不：为什么偏离？

步骤 2："[下一条指令]"
  ...
```

### 需标记的红旗

| 红旗 | 示例 | 修复 |
|------|------|------|
| Agent 必须"猜测" | "选择适当的方法" | 列出具体方法 + 选择标准 |
| 歧义分支 | "适当处理错误" | 枚举错误类型 + 每类的具体处理 |
| 缺失前置条件 | "解析文件" | 指定使用哪个解析器，期望什么格式 |
| 未定义输出 | "报告发现" | 提供确切输出模板 |
| 隐式假设 | "优化查询" | 定义"优化"的含义（速度？内存？可读性？） |

## Layer 3：边界情况测试

### 标准边界情况矩阵

| 边界情况 | 预期行为 | 处理策略 |
|---------|---------|---------|
| 空/ null 输入 | 优雅错误消息，不崩溃 | 输入验证作为第一步 |
| 文件未找到 | 具体错误 + 建议修复 | 处理前检查存在性 |
| 缺失依赖 | 清晰的安装说明 | 列出依赖 + 安装命令 |
| 超大文件（>1000 行） | 分块处理，标注边界 | 大小检查 → 分割策略 |
| 二进制/非文本文件 | 拒绝并解释 | 读取前检测类型 |
| 权限被拒 | 用户友好错误，建议修复 | 捕获权限异常 |
| 畸形内容 | 部分恢复或明确失败 | Schema 验证 + 错误详情 |
| 编码问题（UTF-16/BOM） | 透明处理 | 在读取操作中指定编码 |
| 操作系统特定路径 | 在 Windows/Linux/macOS 上工作 | 始终使用 `/`，处理 `C:/` vs `/home/` |
| 并发修改 | 检测并警告 | 检查文件时间戳/hash |

### 领域特定边界情况

为你的 skill 的特定领域添加行：

| 你的领域边界情况 | 预期行为 |
|-----------------|---------|
| [例：空 SQL 表] | [例：返回空结果集，而非错误] |
| [例：缺失配置文件] | [例：使用默认值并警告] |
| [例：网络超时] | [例：重试 3 次，指数退避] |

## Layer 4：架构测试

### 清单

| # | 检查项 | 通过？ | 备注 |
|---|-------|-------|------|
| 1 | SKILL.md ≤ 500 行？ | | 如超出：将内容移到 references/ |
| 2 | 大段内容已卸载到 references/？ | | 正文应仅为精简概述 |
| 3 | references 是扁平的（无嵌套目录）？ | | 最大深度：SKILL.md → references/*.md |
| 4 | 所有路径使用正斜杠 `/`？ | | 绝不 `\` |
| 5 | 无 README/CHANGELOG/人工文档？ | | 删除所有非 agent 面向文件 |
| 6 | skill.config.yaml 存在？ | | 即使是单 skill 也需要 config |
| 7 | scripts 是小型 CLI 工具？ | | 不是库，不是框架 |
| 8 | description ≤ 1024 字符？ | | Frontmatter 大小限制 |
| 9 | 名称 ≤ 64 字符，kebab-case？ | | 命名规范 |
| 10 | examples 包含正向 AND 负向触发？ | | 两个方向都测试 |
| 11 | references > 100 行有目录？ | | 帮助局部读取发现 |
| 12 | 无时间/期限信息？ | | 无"2025 年之后"，改用遗留章节 |
| 13 | 术语全篇一致？ | | 一个概念一个术语 |
| 14 | 自由度等级与任务脆弱性匹配？ | | 参见 freedom-levels.md |

## 评估评分卡模板

验证完成后使用此模板为 skill 评分：

```markdown
# Skill 验证报告：[skill-name]

## 各层得分

| 层 | 得分 (0-5) | 备注 |
|-------|------------|------|
| 可发现性 | /5 | |
| 逻辑确定性 | /5 | |
| 边界情况覆盖 | /5 | |
| 架构合规性 | /5 | |
| **加权总分** | **/20** | |

## 关键问题（阻止交付）
1. [问题] → [所需修复]

## 必需问题（交付前应修复）
1. [问题] → [建议修复]

## 可选改进（未来迭代）
1. [问题] → [最好有]

## 交付决策
- [ ] 批准 — 所有关键已解决，必需 ≤ 2
- [ ] 有条件 — 附文档化豁免批准
- [ ] 拒绝 — 关键问题仍存在，返回 Phase 6
```
