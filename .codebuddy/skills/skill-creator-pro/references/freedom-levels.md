# 自由度匹配指南

将指令具体程度与任务脆弱性匹配。这是起草 skill 时**最重要的单一决策**。

## 决策矩阵

```
任务脆弱 / 易出错？
├── 是（一步走错 = 灾难）
│   ├── 必须遵循确切顺序？ → 低自由度（确切脚本）
│   └── 一致性至关重要？    → 低自由度（固定参数）
│
└── 否（多种有效方法）
    ├── 上下文决定最佳路径？  → 高自由度（指南）
    └── 存在首选模式？        → 中自由度（模板）
```

## 等级详情

### 低自由度 — 确切脚本

**使用场景：**
- 数据库迁移（顺序重要，数据有风险）
- 部署命令（不可逆操作）
- 文件格式转换（需要特定标志）
- 安全敏感操作

**指令风格：**
```markdown
运行以下确切命令。不得修改或添加标志：

```bash
python scripts/migrate.py --verify --backup
```
```

**关键特征：**
- 带特定参数的确切命令
- "不得修改"措辞
- 执行零灵活性
- 脚本打包在 `scripts/` 目录中

**来自迁移 skill 的示例：**
> 运行：`python scripts/migrate.py --verify --backup`
> 不得添加额外标志或更改顺序。

---

### 中自由度 — 带参数的模板

**使用场景：**
- 报告生成（结构固定，内容可变）
- 代码生成（模式已确立，细节不同）
- 文档创建（格式受限，数据灵活）
- API 响应格式化（schema 已定义，值可变）

**指令风格：**
```markdown
使用此模板，按需定制：

```python
def generate_report(data, format="markdown", include_charts=True):
    # 处理数据
    # 以指定格式生成输出
    # 可选包含可视化
```
```

**关键特征：**
- 伪代码或骨架代码
- 带合理默认值的参数
- 在边界内允许一些适配
- 清晰结构，灵活填充

**来自报告 skill 的示例：**
> 使用此模板结构。根据分析类型调整章节标题。
> 始终包含执行摘要和建议章节。

---

### 高自由度 — 指南与启发式规则

**使用场景：**
- 代码评审（上下文决定什么重要）
- 架构决策（多种有效方法）
- 内容编辑（需要判断）
- 研究综合（模式从数据中浮现）

**指令风格：**
```markdown
1. 分析代码结构和组织
2. 检查潜在 bug 或边界情况
3. 提出可读性和可维护性的改进建议
4. 验证是否遵守项目规范
```

**关键特征：**
- 编号步骤作为指南
- Agent 对每个决策使用判断
- 无确切输出格式指定
- 启发式规则引导但不命令

**来自代码评审 skill 的示例：**
> 1. 读取所有目标文件并映射依赖关系
> 2. 对每个文件检查：命名、错误处理、边界情况、安全性
> 3. 优先排序发现：关键 bug > 设计问题 > 风格琐事
> 4. 输出含行号和修复建议的结构化报告

---

## 常见错误

| 错误 | 问题 | 修复 |
|------|------|------|
| 对数据库迁移使用高自由度 | Agent 可能跳过 `--backup` | 使用低自由度 + 确切脚本 |
| 对代码评审使用低自由度 | Agent 无法适应上下文 | 使用高自由度 + 指南 |
| 完全不指定自由度 | 指令风格不一致 | 在 Phase 2（架构设计）时决定 |
| 在一个工作流中混用自由度等级 | Agent 对约束感到困惑 | 每步选一个等级，记录选择 |

## 实践中的自由度

在架构设计 skill（Phase 3）时，标注每个工作流步骤：

```markdown
## 工作流
1. [低] 验证输入格式          → 确切验证脚本
2. [中] 解析和规范化数据     → 带配置选项的模板
3. [高] 分析并提取洞察       → 指南 + 启发式规则
4. [中] 生成报告              → 固定结构，自适应内容
5. [低] 将输出写入文件        → 确切写入命令
```

这种混合方法在安全性（重要的地方）和灵活性（有价值的地方）两方面都做了优化。
