# 命令参考

PVM 是一个 CLI 工具，语法为 `pvm <command> [arguments] [flags]`。
下面按功能分组列出所有命令。

## 全局参数

| 参数 | 说明 |
| ---- | ---- |
| `--verbose, -V` | 显示详细输出 |
| `--quiet, -q` | 抑制非必要输出 |
| `--user, -u` | 操作用户级配置（默认作用域） |
| `--local, -l` | 操作项目级配置（`.pvmrc`） |
| `--system, -s` | 使用系统已装版本（仅 `use` 可用） |
| `--mirror, -m` | 使用国内镜像下载（默认） |
| `--official, -o` | 强制使用官方源 |
| `--force, -f` | 强制重装 / 强制移除 |

## 流水线（pvm.yaml）

项目根目录放一个 **`pvm.yaml`**（人手写，pvm 只读）。规则只有四条：

```yaml
name: my-app            # 项目名（可选）

install: pnpm i         # 1) 名字: 命令 = 一条命令
lint: pnpm lint
test: pnpm test
build: pnpm build

check:                  # 3) parallel: 加列表 = 同时执行
  parallel: [lint, test]

release:pro:            # 2) 名字: 加列表 = 从上到下依次执行，失败即停
  - install
  - check               # 4) 步骤名等于某条流水线名 = 引用，否则当命令执行
  - build
  - pvm pkg go --entry . --output dist/app
```

| 规则 | 说明 |
| ---- | ---- |
| 顺序 | 列表内从上到下执行；连续命令共用一个 shell（`cd` 会保留）；任一步非零退出即停止 |
| 并行 | `parallel: [a, b]` 同时执行；每个分支独立进程，输出带 `[名字]` 前缀；任一失败即终止其余 |
| 引用 | 步骤名等于某条流水线名时展开该流水线；循环引用在 `pvm run` 时直接报错 |
| 并行位置 | 可写在顶层，也可写在列表里的某一项，两种写法等价 |
| 查找 | 从当前目录**向上**找最近的 `pvm.yaml`（`.yml` 兜底）；工作目录 = 其所在目录，从任何子目录执行都一样 |
| Shell | Unix 用 bash；Windows 优先 pwsh（PowerShell 7），未装回退 5.1——5.1 不支持 `&&`/`\|\|`，会提前报错并给改法 |
| 前置 | 执行前自动安装并激活 `.pvmrc` 声明的版本，流水线里不需要写环境安装命令 |

```bash
pvm run                          # 列出全部流水线（带一行概要）
pvm run release:pro              # 执行
pvm run release:pro --dry-run    # 树形打印执行计划，不执行
pvm run -C services/api pkg      # 在指定目录查找 pvm.yaml
pvm run fail                     # 失败时输出步骤名 + 退出码，且后续步骤不执行
```

:::tip 给 AI / 模型使用
`pvm run` 的输出就是项目的「能力清单」：安装、运行、构建、打包各是什么命令一目了然。
模型不需要读 README、也不用猜 `npm run build` 存不存在——一条命令拿到全部入口，
执行失败时输出会直接指出是哪一步、退出码多少。
:::

:::info 为什么不放 `.pvmrc` / `package.json`
`.pvmrc` 是 pvm 自动读写的版本声明文件（`pvm use --local` 会整体重写它）；
`package.json` 属于 npm，Go / Python 项目没有。`pvm.yaml` 与运行时无关，前后端通用。
:::

## 二进制打包（pvm pkg）

把项目打成单可执行文件，三种运行时共用同一套参数。

| 命令 | 内部方案 | 说明 |
| ---- | ---- | ---- |
| `pvm pkg go --entry .` | `go build -trimpath -ldflags "-s -w"` | 交叉编译自动 `CGO_ENABLED=0`，静态产物 |
| `pvm pkg node --entry src/main.js` | 官方 SEA（Node ≥ 20） | esbuild bundle → blob → postject 注入；跨平台时自动下载对应 node 底座（缓存 `~/.pvm/cache/pack-node/`） |
| `pvm pkg python --entry app.py` | PyInstaller `--onefile` | 缺失时自动 pip 安装；**不支持交叉编译** |

### 目标平台（--type）

| 取值 | 行为 |
| ---- | ---- |
| 省略 / `all` | **5 平台全量**（默认）：`windows/amd64`、`linux/amd64`、`linux/arm64`、`darwin/amd64`、`darwin/arm64` |
| `host` | 仅当前平台 |
| `win` / `linux` / `mac` | 该系统常用架构（win=amd64；linux、mac=amd64+arm64） |
| `linux-arm64` | 系统-架构，只打一个 |
| `win,linux` | 逗号分隔多选，自动去重 |

产物命名：多目标时在 `--output` 扩展名前插入 `-<os>-<arch>`（`dist/app` → `dist/app-linux-amd64`）；
Windows 目标自动补 `.exe`，非 Windows 目标自动去掉误写的 `.exe`。

### 参数

| 参数 | 说明 |
| ---- | ---- |
| `--entry <path>` | 入口：node/python 是脚本，go 是包路径（默认 `.`） |
| `--output <path>` | 产物路径，默认 `dist/<入口主干名>` |
| `--include <src>` | 随产物分发的文件/目录（可重复），见下节 |
| `--external <pkg>` | node：esbuild 不打包的模块（可重复），如 `--external pino-pretty` |
| `--libc <kind>` | node linux：`default`（官方，glibc ≥ 2.28）/ `legacy`（glibc-217，CentOS 7 可用） |
| `--base <file>` | node：完全自定义基座二进制（优先级最高，需配单个目标） |
| `--bundled <file>` | node：已 bundle 好的入口，跳过 esbuild |
| `--zip` | 每个产物额外打一个同名 zip |
| `--verbose` | 透传 esbuild / pyinstaller 日志（默认只打结果） |

### 配置文件一起进产物（--include）

```
--include config.yaml                包内 config.yaml
--include assets                     包内 assets/...
--include assets/                    只打内容（无 assets 前缀）
--include config.yaml:conf/app.yaml  包内改名（python 只能改目录，不能改文件名）
```

| 运行时 | 落到哪 | 代码里怎么读 |
| ------ | ------ | ------------ |
| node | SEA `assets`（≥ 20.12） | `require('node:sea').getAsset('config.json','utf8')` |
| python | PyInstaller `--add-data` | `pathlib.Path(sys._MEIPASS) / 'config.json'` |
| go | 不支持（直接报错） | 用 `//go:embed` 编译期内嵌 |

### 部署机 glibc 比较老

官方 node 基座要求 glibc ≥ 2.28；CentOS 7（2.17）会报 `GLIBC_2.28 not found`。
加 `--libc legacy` 自动下载同版本的 glibc-217 构建：

```bash
pvm pkg node --entry src/app.ts --output dist/app --type linux-amd64 --libc legacy
```

SEA 注入的哨兵哈希随 Node 版本变化，pvm 从基座二进制扫描实际值，不硬编码，换基座不会失配。

```bash
pvm pkg go --entry . --output dist/app                     # 5 平台
pvm pkg go --entry . --output dist/app --type host         # 仅当前平台
pvm pkg node --entry src/main.js --output dist/app --zip    # 5 平台 + zip
pvm pkg python --entry app.py --output dist/app            # 仅当前平台（不能交叉）
```

:::warning PyInstaller 不支持交叉打包
`pvm pkg python` 的 `--type all` 会自动收敛到当前平台；显式指定其他平台会直接报错，
避免产生"已打全平台"的错觉。需要多平台分发时，请在各目标平台分别执行（如 CI matrix）。
:::

## 压缩（pvm zip / unzip）

```
pvm zip <src...> -o app.zip [-x <glob>] [--reproducible]
pvm unzip app.zip [-o <dir>] [-l]
```

| 参数 | 说明 |
| ---- | ---- |
| `-o, --output` | zip 输出路径（默认 `<首个源名>.zip`）；unzip 为解压目录（默认当前目录） |
| `-x, --exclude` | 排除匹配的文件/目录（可重复），如 `-x node_modules -x "*.map"` |
| `--reproducible` | 固定时间戳与权限，同样输入得到逐字节相同的 zip |
| `-l, --list` | 只列出内容，不解压 |

目录写法同 `cp -r`：`dist` 保留外层目录名，`dist/` 或 `.` 只打目录内容。

解压会拒绝 zip-slip 路径（`../../evil.txt`），限制单文件 2 GB / 总量 10 GB / 10 万文件，
GBK 文件名自动转码。
