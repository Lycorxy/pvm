# 故障排查

| 现象 | 可能原因 | 排查 / 解决 |
| ---- | -------- | ----------- |
| 普通终端装包**永远失败**，用管理员身份打开才成功 | 曾以管理员运行安装器 / `pvm setup` / `pvm install`，`~/.pvm` 下的文件归 Administrators 所有，普通权限进程写不进去（删除重装也无效，普通权限删不掉这些文件） | 运行 `pvm repair-owner`（弹 UAC 修复一次），之后用**普通权限**终端重装包即可。新版以管理员跑 `pvm setup` 会自动把文件所有权归还给当前用户，不会再复发 |
| `pvm` 命令找不到 | PATH 未包含 shims | `pvm setup-path` 并检查用户 PATH |
| `node` 仍是系统 / nvm 旧版本 | 系统 PATH 中有 `D:\node` 等覆盖了 pvm shims | 重跑 `pvm setup`，确认 UAC 后把 pvm shims **前置到系统 PATH 最前**；不想提权用 `pvm setup --no-elevate` 仅报告冲突 |
| `pvm use node@18` 后 `node -v` 没变 | IDE 缓存了旧的 PATH | **完全退出 IDE 再重开**（不要只用 reload window） |
| 装了版本但命令没有 | shim 未生成 | `pvm reshim` |
| 安装报 403 / GitHub 限流 | 默认镜像源偶发 | 加 `--official` 或等待自动降级重试 |
| `pvm use` 不生效 | 当前目录无 `.pvmrc` 且用户全局也为空 | 先 `pvm use node@x` 写用户默认 |
| 版本解析异常 | 环境变量 / `.pvmrc` / 全局 冲突 | `pvm diagnostics node` 看完整链路 |
| shim 与版本不一致 | 手动删过版本目录 | `pvm validate --auto-fix` |
| VSCode 识别不到 Git Bash | git/current/bin 未加入用户 PATH | `pvm use git` 重新触发 PATH 更新，然后完全退出 VSCode 重开 |
| `pvm use git` 报 `install dir not found` | pvm 把自己的 git 路径当系统 git 导致循环 junction | `pvm install git` 重新下载即可 |
| 同一环境多项目并发，git 提交人串了 | 仓库身份用了 `--global` 配置，互相覆盖 | 每个仓库各自 `git config user.name "X"`、`git config user.email "x@y"`（**local 配置优先于 global**，仓库间天然隔离，互不影响） |
| `pvm run` 报 `uses '&&' or '||', which Windows PowerShell 5.1 does not support` | 未装 PowerShell 7，Windows 回退到 5.1（不支持 `&&`/`\|\|` 串联） | 安装 PowerShell 7（`winget install Microsoft.PowerShell`，pvm 会自动优先使用）；或把命令拆成多步 / 用 `;` 串联 |

:::tip 关于 IDE 环境变量缓存
VSCode / CodeBuddy 等编辑器在启动时读一次 PATH 并缓存。切换版本后必须**完全退出编辑器**（File → Exit），
再重新打开，内置终端才会拿到新版本的 node / git。仅 "Reload Window" 不够。
:::

## 诊断命令速查

```bash
pvm doctor                  # 安装健康度
pvm setup-path              # PATH 检查
pvm repair-owner            # 修复 ~/.pvm 文件所有权（管理员装完普通权限装包失败）
pvm reshim                  # 重建 shim
pvm which <cmd>             # 命令真实路径
pvm diagnostics <runtime>   # 某运行时解析链路
pvm validate --auto-fix     # 一致性校验+自动修复
```

:::warning 注意
修改 PATH 或安装新版本后，请**重启终端 / IDE**，否则可能仍读到旧环境。
:::
