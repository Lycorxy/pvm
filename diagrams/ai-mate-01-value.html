PROBLEM → SOLUTION → VALUE
一个 AI 助手，四个项目，零环境翻车
多应用开发的病根只有一个：环境状态不跟着项目走。pvm 用四层解法逐条击破。
翻车 01

版本错乱

全局装的是 Node 22，老项目要 18 —— lockfile 被静默重写，CI 红了，查半天才发现是环境。

→
.pvmrc

声明式环境版本跟着项目走

cd 进项目那一刻环境就位：不 use、不切终端、不用问。去隔壁项目，自动变。

零切换成本
翻车 02

环境试错循环

装了→版本不对→PATH 又错，一分钟的活折腾半小时，还全发生在你的全局环境里。

→
pvm skill

环境自愈AI 自助诊断

5 项体检，每项失败自带「下一步」：装、接管、修 PATH。AI 修复后复验到全绿，闭环不折腾人。

故障自闭环
翻车 03

命令靠猜

npm run build？make release？猜错 → 翻 README → 再猜。文档写得再全，AI 也未必读到那一段。

→
pvm.yaml

本地流水线项目的操作说明书

pvm run --list 一屏列出项目全部能力；@ 引用串行、& 后台并发，AI 接手即上手。

上手零猜测
翻车 04

全局污染连带崩盘

为修 B 升了全局包、改了 PATH —— B 是好了，A 和 C 早上还好好的，晚上神秘挂掉。

→
项目级隔离

环境按目录生效互不可见

环境状态只在本项目目录内生效，项目之间互不可见、互不污染，一台机器装四套运行时。

修 A 不炸 C
单二进制 9 种运行时 项目级隔离 Windows 原生 无守护进程
